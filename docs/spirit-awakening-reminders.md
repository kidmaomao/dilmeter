# 精灵实体化充能提醒

在 CD 提醒中选择对应武器的精灵实体化技能后，使用服务器充能显示进度；达到 100% 时图标亮起。支持现代精灵技能 `35111–35130`，包括补入技能库的占星球实体化 `35130`。多个武器分别保存充能；不使用固定秒数推算恢复。

佩戴 `58015` 连续实体化并触发时，服务器保留满充能，提醒也保持亮起。额外一次使用消耗充能后，图标恢复充能状态。仅佩戴特技不会被当成触发，不从伤害或实体化效果 Buff 猜测是否可再次使用。

优先通过完整精灵列表把充能归到对应武器。中途开始捕获、未收到列表时，也可在首次满充通知或普通实体化消耗充能时自动建立对应关系，随后持续显示该武器的充能。识别前的零散充能不会猜测归属；重新登录或换线也可补齐列表。切换角色或捕获连接时清除旧状态；重新打开前端页面则读取当前已知充能。

## 抓包依据

本地样本：`packet_capture_1791980232.pcapng`，配套 `packet_log_2026-10-14_20-17-12.ndjson`。更早的 `packet_capture_1791373369.pcapng` 用于交叉检查施放包。

- `44582` 是按精灵槽位发送的列表/增量更新：首项为槽位数，随后每个槽位先给字段掩码；未变化的槽位仍携带零掩码。
- 完整掩码 `0xffffffff` 带 16 个字段。位 `0` 是武器类型（short），位 `14` 是充能（int）。样本充能范围 `0–60000`，`60000` 对应 100%；常见增长为 `2000`。实体化用掉后归零。
- 武器类型 `1–20` 映射到技能 `35110 + 类型`。10 月 14 日完整列表中有 9 个武器类型，实际本机施放为类型 `20` / 技能 `35130`。
- `27016 [short 技能, long 目标]` 的双字段形式中，目标不是唯一动作编号。修正该形式的去重，才能记录同一目标上的后续实体化。
- 两次保留充能的施放同时出现 `21101` 的连续实体化再使用提示。实现直接采用充能更新，不依赖语言相关的提示文字。
- `CC 577` 属于实体化效果，不代表充能已满或连续实体化可用。

## 验证

CN/RT 共用目录与 OT 目录同步实现：

- Go 测试覆盖列表/增量解析、坏包拒绝、武器独立状态、重连清理、前端初始同步、同目标重复施放、满充门槛、连续实体化保持和消耗，以及原生提醒实际绘制与技能栏遮罩。
- 前端 `npm run verify:spirit-awakening` 覆盖 20 个技能、设置保存、后台事件处理、满充判定与重连。
- 本地回放：设置 `DILMETER_SPIRIT_PCAP` 指向上述 10 月 14 日样本，运行 `go test ./cmd/dilmeterapi -run TestReplaySpiritAwakeningCapture -v`；断言 9 类武器与完整的 7 次施放序列。

实包证据来自 CN。其他武器使用统一字段映射；OT 同步实现和回放通过不等于已经取得 OT 实服样本。旧精灵的 `21009 / 22005 / 22006 / 30401 / 35101` 不套用现代精灵的充能协议。

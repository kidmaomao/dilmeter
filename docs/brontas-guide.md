# 二王 50% 射线与走位辅助

CN、RT、OT 共用此功能。通过「Boss 特殊机制 → 布隆塔纳斯 50% 落石方位」启用「显示实战射线提示」，可在覆盖层预览中检查方向、大小和位置。旧配置继续兼容；走位辅助默认关闭。

## 显示与操作

- 落石出现后先显示全场点位；角色进入点位后只显示该点位九宫格覆盖的射线。
- 右侧横线、竖线倒计时分别属于当前脚下的射线，跨入另一条射线时重新匹配。
- 实线箭头是当前一步，虚线是下一次转弯；每步只横向或纵向走一格，不指引斜线。
- 蓝色「等拍」表示留在当前格等节奏，绿色「移动」表示按箭头移动，红色「快躲」表示紧急撤离，灰色「暂无指引」表示暂无有效方向。
- 默认朝外，即从场地中心朝外看；可选择朝内、朝 12 点、朝 6 点。点位标签仍按真实地图位置显示。

建议第一轮射线前下宠，按当前实线走完一格再转弯，不直接点击两格外的斜角。

## 数据与规划

真实射线来自抓包识别，通过 `EventBrontasRay` 驱动；角色位置只接受当前本人实体。骑宠时的宠物速度不会当成本人跑速。下宠后可暂用最近 5 秒内、至少两次本人跑动采样得到的速度，以 60% 计算保守起步预算，等新的本人采样到达后更新。缓存不用于推算人物位置。

规划使用横纵三条相接通道的 3×3 网格，检查沿途、到达及下一次转弯的已知射线。等待节奏由脚下实际预警的绝对时间和本人移动预算计算，不从入圈开始固定计时，也不将全场射线频率当成个人步频。

已发出的目标在当前一步内保持稳定；尚未发出方向且尚未起步的拐点，可选择另一侧已核验的直角折线。失效箭头按绝对时间撤下，前端不能仅凭倒计时结束自行放出旧箭头。

覆盖层通过最新状态推送与逐帧绘制更新；移动位置预测最多 700 毫秒，数据过期停止显示该位置。CN/RT 与 OT 保留各自抓包来源检查，离线包不冒充实时数据。

## 已知边界与验证

射线判定后的伤害持续时间暂按 600 毫秒建模，另加 150 毫秒时间余量，仍待实战校准。红色紧急撤离用于降低已处于危险中的暴露，不代表无伤保证。没有每条射线的目标来源标记，不推测尚未出现的射线或随机机制。

Go 回归覆盖真实输入、正交路径、固定目标、起步节奏、过期撤回、未来射线交叉、下宠测速缓存和非本人实体隔离。前端 `verify:brontas-guide` 覆盖四种方向、独立倒计时和行动提示；CN、RT、OT 后端与两套前端均需验证。

2026-10-31 的 24 段本地记录回放中，14 段第一步指引提前；全部 24 段提前量中位数为 0.521 秒。另一次已成功实战的最后阶段回放未出现未走完当前一步就改目标的情况。回放结果不等于实战成功率。个人抓包、录像、配置均不进入仓库或安装包。

## 外部识别器兼容接口

下列接口保留给独立识别器；正常使用内置抓包识别不需要调用。

原生代码可调用 `submitBrontasGuideFrame`；独立识别器可向本机发送：

```
POST http://127.0.0.1:8030/api/brontas_guide
Content-Type: application/json
```

每 100–200 ms 发送一次**完整观察快照**，包括仍在场的所有射线。收到 `202` 表示已排队，`503` 表示运行时不可用或队列满。仅允许本机访问；拒绝跨站网页、未知字段、非法几何、过期时间和超大请求。

最小方向提示快照（下面的时间是结构示例，不能直接发送）：

```json
{
  "session": "detector-session-1",
  "sequence": 1,
  "bossId": "实际二王实体ID",
  "observedAtMs": 1700000000000,
  "active": true,
  "clock": 12,
  "geometryComplete": false,
  "rays": [{
    "id": "ray-1",
    "axis": "vertical",
    "warningAtMs": 1700000000000,
    "lethalAtMs": 1700000001600,
    "endsAtMs": 1700000002300
  }]
}
```

- 时间均为本机 Unix 毫秒，必须与 Dilmeter 使用同一时钟。`observedAtMs` 是最新实际观察时间，不能通过重发来更新旧观察。`sequence` 在同一 session 中递增。
- `warningAtMs` 是这条射线首次预警时刻；`lethalAtMs` 是实际致命时刻。若识别器提供“剩余等待时间”，应在**识别当时**换算绝对时刻。重复快照不能重启计时。
- `endsAtMs` 是危险结束时刻，可省略或传 0；未知结束时间的射线按持续危险处理，直到后续实际观察确认消失并从快照中移除。不能用固定值提前宣布安全。只有方向与致命等待时间也能接入。
- `clock` 为旋转校准前的矿石点位（12/3/6/9），0 表示未知。它是实际点位/团队分工，不按顺序给全队自动分配同一个位置。
- `axis` 是地图轴，不是人物面朝方向。随机、对侧与自身来源射线都按同一规则加入，不假设“队友死亡必定额外生成一次”。
- 机制结束发送 `active:false`。转场、断线重置或矿石消失也会撤销显示。断流 500 ms 自动停止引导。

要开启区内箭头，在快照中增加：

```json
{
  "geometryComplete": true,
  "player": { "x": 0, "y": -0.35, "radius": 0.08, "speed": 1.2 }
}
```

同时给每条射线增加 `offset` 和 `halfWidth`（数值）。坐标原点是**当前选定落石区中心**，该区半径为 1，世界 X 正方向向右、Y 正方向向上。`player.radius` 为人物碰撞半径，`speed` 单位为落石半径/秒。横线中心为 `y=offset`，纵线中心为 `x=offset`。所有射线必须转换到同一坐标系，包括对侧射线；不能把另一点位局部坐标直接混入。归一化需要实际落石区域半径，内置识别器已有独立的点位转换，外部输入仍须自行提供正确几何。

`geometryComplete:true` 代表当前观察覆盖所有有关射线且几何已校准。部分识别、镜头投影不确定、射线宽度未知时应使用 false。

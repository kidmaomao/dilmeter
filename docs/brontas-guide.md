# 布隆塔纳斯 50% 桌面走位覆盖层（开发版）

本改动基于 `kidmaomao/dilmeter` 主分支 `d677c3842809b87a93d44345069b47c6807d4071`。代码同步到 `cn-rt` 和 `ot`；未发布正式版本。

## 已完成与当前缺口

已接入 Dilmeter 自带的 Windows 透明置顶窗口，沿用锁定时鼠标穿透、游戏前台显示、解锁拖动和 DPI 缩放。日常渲染使用程序内嵌的 WebView2；GDI 后备绘制也支持新卡片。无需打开外部浏览器。

实际落石继续由现有 `21200/21201`、矿石 `49205` 和二王 `7602` 血量判定驱动。只有真实矿石存在且来源 bossId 匹配时才显示实时提示。

**这个主分支没有二王射线的已验证解码器。现有 `publishBossLaserPacket` 识别的是三王技能 `52401`。本改动没有凭空指定二王 opcode。** 新增了射线观察输入接口，等待对接已有识别器。没有接入时显示“等待射线数据”，不会自动生成射线或启动 1.6 秒计时。

| 输入能力 | 显示内容 |
| --- | --- |
| 只有仓库现有落石识别 | 实际落石位置、等待射线数据 |
| 射线方向及绝对致命时间 | 横/纵轴提示、最早致命倒计时；不猜左右 |
| 完整人物及射线几何 | 当前落石区内的移位线、箭头、目标圆点 |
| 人物仍在区外 | 提示进入已分配落石区；暂不规划区外路径 |
| 数据过期/无法及时到达 | 撤掉箭头，明确显示原因 |

这是区内直线路径辅助，不是世界地面投影、全地图寻路或自动操作。站位索引以地图方向为准；镜头转动后需使用方向校准。人物半径、落石区半径、移动速度和射线宽度必须通过实战校准，当前默认测试几何不能直接视为游戏测量值。

验证记录：CN/RT、OT 的 Go 检查均通过（排除了环境禁止本机网络连接的 `TestOnlineUpdatePipelineDownloadsAndValidatesReleaseZip`）；两版前端类型检查及生产构建通过。CN/RT 的矿石、Boss 提醒、配置、爆发提醒、枪骑士和秘术 KPI、战斗记录、桌面挂载检查通过。开发版已在本机启动，设置页可见新增选项；尚未完成真实游戏覆盖、鼠标穿透和时序校准。

## 在 Dilmeter 中打开

在 Boss 特殊机制设置的“布隆塔纳斯 50% 落石方位”中，勾选“启用方位提示”和“显示走位提示（需射线输入）”，保存。使用“预览覆盖层”检查桌面显示和位置；预览明确标注“预览”，箭头到期后撤回。预览按钮不会伪造战斗数据。

沿用现有覆盖层总开关、锁定/解锁以及 X、Y、大小和方向校准设置。新增字段 `bossMechanics.brontasRocks.guidanceEnabled` 默认关闭，旧配置可继续读取。

## 接入已有识别器

原生代码可调用 `submitBrontasGuideFrame`；独立识别器可向本机发送：

```
POST http://127.0.0.1:8030/api/brontas_guide
Content-Type: application/json
```

每 100–200 ms 发送一次**完整观察快照**，包括仍在场的所有射线。收到 `202` 表示已排队，`503` 表示运行时不可用或队列满。仅允许本机访问；拒绝跨站网页、未知字段、非法几何、过期时间和超大请求。

最小方向提示快照（下面的时间是结构示例，不能直接发送）：

```json
{
  "session": "detector-session-1",
  "sequence": 1,
  "bossId": "实际二王实体ID",
  "observedAtMs": 1700000000000,
  "active": true,
  "clock": 12,
  "geometryComplete": false,
  "rays": [{
    "id": "ray-1",
    "axis": "vertical",
    "warningAtMs": 1700000000000,
    "lethalAtMs": 1700000001600,
    "endsAtMs": 1700000002300
  }]
}
```

- 时间均为本机 Unix 毫秒，必须与 Dilmeter 使用同一时钟。`observedAtMs` 是最新实际观察时间，不能通过重发来更新旧观察。`sequence` 在同一 session 中递增。
- `warningAtMs` 是这条射线首次预警时刻；`lethalAtMs` 是实际致命时刻。若识别器提供“剩余等待时间”，应在**识别当时**换算绝对时刻。重复快照不能重启计时。
- `endsAtMs` 是危险结束时刻，可省略或传 0；未知结束时间的射线按持续危险处理，直到后续实际观察确认消失并从快照中移除。不能用固定值提前宣布安全。只有方向与致命等待时间也能接入。
- `clock` 为旋转校准前的矿石点位（12/3/6/9），0 表示未知。它是实际点位/团队分工，不按顺序给全队自动分配同一个位置。
- `axis` 是地图轴，不是人物面朝方向。随机、对侧与自身来源射线都按同一规则加入，不假设“队友死亡必定额外生成一次”。
- 机制结束发送 `active:false`。转场、断线重置或矿石消失也会撤销显示。断流 500 ms 自动停止引导。

要开启区内箭头，在快照中增加：

```json
{
  "geometryComplete": true,
  "player": { "x": 0, "y": -0.35, "radius": 0.08, "speed": 1.2 }
}
```

同时给每条射线增加 `offset` 和 `halfWidth`（数值）。坐标原点是**当前选定落石区中心**，该区半径为 1，世界 X 正方向向右、Y 正方向向上。`player.radius` 为人物碰撞半径，`speed` 单位为落石半径/秒。横线中心为 `y=offset`，纵线中心为 `x=offset`。所有射线必须转换到同一坐标系，包括对侧射线；不能把另一点位局部坐标直接混入。归一化需要实际落石区域半径，仓库目前只有矿石中心坐标。

`geometryComplete:true` 代表当前观察覆盖所有有关射线且几何已校准。部分识别、镜头投影不确定、射线宽度未知时应使用 false。

## 决策规则与边界

1. 先验证观察的新鲜度、bossId 和真实矿石点位。
2. 检查人物当前位置，安全且无需移位时提示保持；区外不给未经校准的入场路线。
3. 在区内候选落点中检查直线移动全过程及到达后的停留；同时考虑全部已观察射线。允许在预警尚未致命时穿过，但禁止穿过已生效的射线。
4. 目前使用 300 ms 反应预算、150 ms 时间余量和 0.03 半径空间余量。它们是待实战验证的工程参数，不是游戏机制常量。移动速度、观察误差、网络及显示延迟都可能使提示不再适用。
5. 箭头会在“来不及再开始这条路线”时提前到期，即使快照尚未达到 500 ms 超时。渲染端也独立检查到期，防止后端或轮询中断后遗留箭头。
6. 不推测未出现的随机射线，不保证下一帧仍然安全，不注入按键或控制人物。

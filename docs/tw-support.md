# 台服射线与繁体界面

## 射线漏报原因

2026-09-28 用户提供的台服抓包中，普通米耶尔（种族 7603）所属的三个碎片（7604、7605、7606）通过 **0xAFFA / 45050** 宣告神剑射线。原有代码仅分派 0xAFE7、0xAFE8、0xAFEF、0xAFF0，因此完全没有生成射线技能事件。

与已验证的 2026-09-12 国服 0xAFF0 / 45040 相比，变化的是封包编号；台服载荷仍以 `Short(52401), Byte(0)` 开头。三个启动信号的时间分别是 `1790606383566`、`1790606383574`、`1790606383574` 毫秒，射线伤害发生在 `1790606388597` 毫秒，约晚 5 秒。

仅 OT 补充 0xAFFA 分派，并保留严格的字段类型、技能号和阶段校验，以及按 Boss 所有者的 250 毫秒去重。相同编号中的神枪 `Short(52402), Byte(1)` 和取消 `Short(0), Byte(1)` 不触发射线。悔恨种族的同类信号通过合成测试覆盖；这份实战样本只包含普通难度。CN、RT 不做此次改动。

原始抓包和角色记录不进入 Git。设置 `DILMETER_TW_LASER_PCAP` 为本机抓包路径后，可运行 `go test ./cmd/dilmeterapi -run TestReplayTWSeptember2026Laser -count=1`。回放预期为一次射线事件、一次提示音和 5 秒倒计时。

## 使用方式

- 顶部「语言」可选「简体中文」或「繁體中文」，即时生效并保存。界面文字转换使用随程序打包的 OpenCC，不依赖在线翻译。角色名称、文件名与输入框内容保持原值。
- 顶部「资料」可选 CN 或 TW，再点「载入资料」。界面语言和资料服务器彼此独立。
- TW 来自 [Prilus Mabi Tool](https://prilus.gitlab.io/) 使用的 `https://mabires.pril.cc/` 服务。首次载入需联网；后续按服务器分别缓存，更新失败可使用已经下载的同服资料。
- 「重新下载」强制更新。下载、解压、校验或保存失败时不替换当前名称与选择，不静默混用 CN 和 TW。
- TW 技能、状态和 Boss 名称不再被简体转换或国服名称特例覆盖；搜索同时接受简繁输入。
- 资料选择只影响资料显示，不改变服务器地址和抓包协议。台服抓包继续使用 OT 的服务器设置。
- CN 选项保留内置数据；OT 的现有手动外置资源包仍按原方式覆盖这个入口。

## 开发验证

在 `ot/front` 运行 `npm run verify:tw-resources`、`npx vue-tsc --noEmit` 和 `npm run build`。资源测试覆盖选服隔离、名称特例、语言独立性、简繁搜索、保存选择、离线缓存、下载失败、损坏数据和切回 CN。新增 UI 文案应在显示处使用 `$ui` / `uiText`；Vuetify 标题数组可用 `$uiItems`，不要转换选择值或原始角色名称。

在 `ot` 运行 `go test ./...`。台服原始回放验证解析、实体所有者、去重与原生提醒的完整路径。

### 本次验证结果（2026-09-28）

- OT 的 Go 全套测试通过，包括用户提供的台服原始抓包回放；普通难度产生一次提醒和 5 秒倒计时，悔恨难度由合成数据覆盖。
- 前端类型检查、生产构建和新增 TW 资源测试通过；其余 22 项现有验证脚本通过。
- 浏览器连接真实 Prilus 资源，验证繁体切换、TW 下载、刷新后保留选择，以及载入用户战斗记录后显示台服名称；切回 CN 后名称随之更新。浏览器使用隔离的桌面接口模拟环境，尚未在台服实时战斗中验证测试版。
- 四项现有验证脚本有基线问题：`verify:effective-damage` 引用不存在的导出，`verify:raw-dps`、`verify:packet-dps` 引用缺失脚本，`verify:skill-cooldown` 的无扩展名导入不能由当前 Node 直接解析。相关源码与脚本在本次修改前已存在这些问题，本次未修改。
- CN/RT 的源码与正式程序均未改动；测试程序仅为 OT，尚未正式发布。

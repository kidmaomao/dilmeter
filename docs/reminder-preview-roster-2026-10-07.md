# 爆发预览与多人崩坏窗口（2026-10-07，R4）

适用 CN、RT、OT。R4 包含此前队友设置、本人监测和 TCP 重组修复。

## 最终行为

- 爆发提醒内全部 7 个预览按钮统一显示 8 秒，包括崩坏就绪、小窗、放大、吟唱、生效，以及万钧／力量团聚的吟唱、生效。按钮明确标注 8 秒，再次点击会替换旧预览并重新计时。
- 小窗与大窗共用深色渐变背景和金色边框。技能图标在上，下方保留已知就绪者，同时展示仍在冷却且最早结束的一人。
- 示例小窗：图标 → A 已就绪 → B 6.0s。示例大窗：图标 → A 已就绪 → B 即将就绪 → 大号 6.0s。大窗在最近有人就绪、但 B 尚未进入提前范围时使用「冷却中」。
- A 的就绪状态不会因开始显示 B 而丢失。A 再次释放后移出就绪名单，按新的结束时间参与候选。所有人已就绪时显示就绪名单；未知冷却不虚构就绪。死亡、离开视野、取消监测等原有过滤继续生效。
- 就绪人数增加时窗口高度自动增加，窗口边界与卡片避让同步按实际尺寸计算。数字角色 ID 仅作内部身份键，不显示。
- 「一直显示」和「提前 N 秒放大」仍是独立选项。未开启一直显示时仅在提醒窗口出现；实际游戏的吟唱与生效时长不受预览时长影响。

## 预览消失的原因及修复

原预览从页面发送一帧到实时悬浮窗状态，后端下一次刷新直接覆盖它；此外旧按钮分别使用吟唱秒数、3 秒或 10 秒，时长不一致。

R4 增加专用预览接口，在后端独立保存固定 8 秒的预览。实时状态更新合并预览，不能清除它；预览也保留真实技能与机制数据。显式点击的预览可在普通悬浮提示关闭时显示。到期自动消失，不延长真实战斗状态。

## 验证

- CN、RT、OT 后端测试通过。覆盖实时刷新每 200 毫秒替换状态时的预览存活、7999／8000 毫秒边界、重复点击、正常数据保留和关闭普通悬浮提示后的显式预览。
- 多人回归验证 A 就绪与 B 冷却同屏、跨 3 秒仍保留 A、本人／队友再次释放、冷却减免与重置、就绪音效、未知状态、死亡及排除候选。
- Windows 原生回退绘制验证小窗两行、大窗三行、无数字 ID、统一边框、文字与图标无重叠；前端验证多名就绪者的动态尺寸。
- 两份前端的 TypeScript 检查、爆发配置／预览数据检查和生产构建通过。
- 浏览器挂载实际设置、弹窗和 SkillCooldownOverlay 组件，并连接真实 Go 预览／状态接口；后台每 200 毫秒持续刷新。逐一点击 7 个按钮，第 7753–7763 毫秒均仍可见，8 秒后均正常消失。记录：`artifacts/reminder-ui-20261006/r4-preview-durations.json`。
- 已检查简体与 OT 繁体排版。此验证使用隔离的模拟队友数据，尚未进行真实游戏组队验证。
